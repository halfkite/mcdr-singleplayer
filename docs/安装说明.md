# mcdr-singleplayer 0.3.10：安装与手动模式

适用于 Minecraft 1.21–1.21.11 与 26.1–26.3 的 Fabric / NeoForge 客户端，明确版本清单见 [兼容性记录](0.3.10兼容性与发布.md)，1.21.x 使用 Java 21+，26.x 使用 Java 25+。

## 默认安装

1. 从 Release 选择当前加载器的 `mc1.21.x.jar` 或 `mc26.x.jar` 放入实际游戏实例的 `mods/`，Fabric 同时安装当前游戏版本的 Fabric API，NeoForge 无需 Fabric API，移出旧版桥接 JAR。
2. 启动客户端。首次生成 `mcdr-singleplayer/config.json`，后台安装 MCDR 2.16.0 与运行依赖。进入单人世界后点击聊天中的 `[安装]` 安装 PB 或 CB（含 candy_tools 前置），并按提示启用定时备份与自动删除；已有插件不再显示其安装按钮。
3. 进入单人存档后启动该存档的 MCDR 环境。无需开放局域网。

所有模组设置、共用配置、插件及存档分类均在游戏实例的 `mcdr-singleplayer/`。详细目录、推荐配置、迁移和回档说明见 [自动启动与存档配置](自动启动与存档配置.md)。

本模组监听回环地址，默认端口 25585。端口冲突时修改 `mcdr-singleplayer/config.json` 的 `port` 并重启游戏。不要替换或公开随机 `token`。

## 可选手动模式

需要手动管理 MCDR 时，在 `mcdr-singleplayer/config.json` 设置 `autoStartMcdr: false`。退出自动模式的 MCDR 进程后，解压完整安装包，在解压目录使用计划运行 MCDR 的 Python：

```powershell
python -m pip install mcdreforged==2.16.0
python .\setup_mcdr.py --game-dir 'D:\Minecraft\实例目录' --world-dir 'D:\Minecraft\实例目录\saves\你的存档文件夹' --player '你的游戏名'
& 'D:\Minecraft\实例目录\mcdr-singleplayer\start_mcdr.ps1'
```

`--game-dir` 是含 `mods/` 和 `saves/` 的实际实例目录；`--world-dir` 必须是该实例的已有存档，内含 `level.dat`。`--player` 可省略，填写后追加 owner 权限。脚本生成唯一共用目录 `游戏实例/mcdr-singleplayer/`，保存既有共用配置并修改运行桥接所必需的项目；为指定世界生成独立分类和启动脚本。

生成的脚本在 `mcdr-singleplayer/date/<存档文件夹名>/` 中运行，读取 `config.yml`、`permission.yml`、`plugins/`，代理读取 `config.json`；该存档的 MCDR 日志统一写入 `log/<存档文件夹名>/`。不要直接在共用目录执行不带路径的 `mcdreforged start`，否则插件数据会写入错误位置。手动模式切换世界时停止 MCDR，重新运行配置脚本选择新世界，再启动；自动模式会自行切换。

手动安装 Prime Backup 见 [PrimeBackup适配](PrimeBackup适配.md)。自动模式已包含该插件与适配器，无需重复安装。

## 验证连接

进入所选存档，执行 `/!!spbridge status` 查看绑定、连接和版本；输入 `/!!MCDR plugin list` 检查插件，`/!!pb make 测试备份` 创建备份。主玩家自动获得 MCDR owner。恢复游戏后再执行需要修改世界的命令，单人暂停期间会拒绝执行。

`!!MCDR server stop/restart/kill` 管理代理连接。Prime Backup 回档使用专用适配器，自动保存并退出世界，主菜单提示完成后手动重新进入；不能通过启动代理命令直接打开世界。

## 插件范围

插件相对配置和数据路径按存档工作目录隔离。其他插件指定的固定绝对路径需自行调整；原生 RCON、专用服务端日志格式和通过重启外部 Java 进程打开存档的行为需单独适配。不要同时加载另一个提供 MCDR handler 的插件。

升级前结束备份和回档并关闭客户端；新旧桥接 JAR 不可共存。旧版模组设置与状态自动转移，原外置 MCDR 文件作为导入来源保留。
