## 真实客户端与 Prime Backup

执行 `runClientGameTest`，使用独立测试存档及全新的 `.reference/auto-clean-r4` 共用目录，不操作用户存档。

已验证：

1. 从游戏端启动安装器，创建独立虚拟环境；联网安装 MCDR 与全部 Prime Backup 依赖；下载官方插件并验证 SHA-256。
2. 主菜单只运行控制器；进入世界后启动对应存档进程并加载三件插件。
3. `/mcdr_setup owner` 主动设置当前玩家权限，`/mcdr_setup recommend` 启用推荐配置、重载 Prime Backup 与适配插件。
4. `/!!MCDR plugin reload singleplayer_b` 使用 MCDR 原生命令树返回包含 `singleplayer_bridge` 的补全。
5. `/!!pb make automatic-test` 创建实际备份；把钻石块改成金块，把标记文件从 `before` 改成 `after`。
6. `/!!pb back 1 --confirm` 保存并退出世界，回档前创建安全备份，恢复到 #1；检验标记文件回到 `before`。
7. 控制器在日志中记录等待回档任务，恢复完成后 MCDR 才退出。重新进入原世界自动重新连接，检查方块恢复为钻石块。
8. 进入第二个存档，确认其初始备份配置关闭，未继承第一个存档的数据库；导入第一个存档配置后绑定目标和备份目录仍指向第二个存档。
9. 旧有真实备份、导出 ZIP、暂停拒绝、热重载、持锁时拒绝离线回档、确认回档、玩家背包恢复与断开代理测试继续通过。

真实客户端命令在 23:33 完成，Gradle 报告 `BUILD SUCCESSFUL in 1m 47s`。最后进一步收紧自定义配置文件识别范围，Python 全套测试再次通过；这次收紧不改变已实测的 Prime Backup `config.json` 导入规则。

Fabric 客户端测试框架控制客户端和服务端的 tick 阶段。异步保存退出在测试夹具中通过它的受控客户端阶段调度，避免框架的阻塞退出与 tick 栅栏互相等待；世界保存、释放锁、回档、重开和文件验证均使用真实 Minecraft 与官方 Prime Backup。发行模组仍使用正常 Minecraft 客户端任务调度器。

实际测试环境已有 Python，但测试 MCDR 虚拟环境从零创建并联网安装依赖。缺少系统 Python 时的 Windows x64 静默 Python 安装分支已实现并核对官方文件校验值，本次没有卸载现有 Python 来实测该分支。
