# 0.3.7 目录布局与原生插件数据验证

基线：2026-10-03，Minecraft 26.3 Fabric、Java 25、MCDR 2.16.0、Prime Backup 1.13.1、Chunk Backup 2.0.3、candy_tools 1.0.2。

## 目录修正

- `config.json`、`config.yml`、`permission.yml`、`plugins/` 直接位于 `mcdr-singleplayer/` 根目录。
- `date/<存档文件夹名>/` 是插件进程的工作目录；配置仍由 MCDR API 写入 `config/<插件 ID>/`，插件数据采用原生相对路径，PB 默认 `./pb_files`，CB 默认 `./cb_files`。
- 存档目录不生成单独的 MCDR 配置、权限、插件或 `server/`，游戏文件仍在实际存档中。日志继续归入 `log/`，运行环境继续归入 `runtime/`。
- 自动迁移桥接以前引入的 `runtime/config/`、`data/prime_backup/`、`data/chunk_backup/`。保持已有备份库和策略，保留自定义存储路径；目标备份目录已包含数据时拒绝合并。

## 已执行验证

迁移与控制器的 13 项专项测试通过，涵盖真实 SQLite 数据迁移、数据库字节校验、再次执行的幂等性、原生与旧目录冲突时保留两边的数据，以及控制器运行时阻止移动配置。

真实客户端 GameTest 已通过两轮验证：第一轮启用基础桥接、PB、CB 和自动启动测试，第二轮加强 PB 原生数据库路径断言，复测基础桥接与自动启动。自动流程实际创建独立 Python 环境、安装依赖和 PB、在主菜单等待、进入与切换存档、同步命令、配置导入、保存退出和回档完成后重新进入。

PB / CB 真实客户端回归覆盖创建备份、中文 CB 玩家位置查询、静态和动态槽位、取消回档、回档等待界面、入口锁、控制器等待任务完成和撤销 CB 回档。备份仍使用插件原有选区与存储格式；此版本没有改变游戏线程的保存方式。

额外从旧版真实 PB 备份库迁移到 `pb_files/`，使用官方 PB 读取并校验文件池、导出备份 1。导出 51 个条目，标记文件与 `level.dat` 内容验证通过，原始数据库 SHA-256 保持不变。结果见 `assets/automatic-0.3.7-migration.json`。

全量自动测试、真实 Gradle 构建与安装包归档使用 `scripts/build.ps1`。JAR 和安装包分别归档到新建的 `mod-builds/<时间戳>/`。

## 用户实例迁移与检查

迁移现有实例需先退出 Minecraft，并确认控制器和安装锁释放。保存迁移前的配置、插件、运行脚本、备份数据和旧 JAR 的恢复副本，移动后对 PB 的全部文件逐一比较 SHA-256，并用只读 SQLite 检查数据库。用户实例的详细路径、权限、令牌与数据清单仅记录在该实例 `runtime/migration-history/`，不写入仓库。

其他第三方插件采用自己的原生相对路径，本次不尝试重写其自定义绝对路径。Carpet 玩家数据恢复、自定义维度等未覆盖的游戏场景继续参考 [CB 测试边界](0.3.6ChunkBackup测试记录.md)。
