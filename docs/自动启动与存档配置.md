# 0.4.0：自动安装、随游戏启动与独立存档配置

适用于 Minecraft 1.21–1.21.11 与 26.1–26.3 的 Fabric / NeoForge 客户端，具体版本清单见 [兼容性清单](../compat/versions.json)，Java 版本按对应游戏选择。

## 安装与自动启动

把对应加载器和版本系列的 `mcdr-singleplayer-0.4.0+<加载器>+mc<系列>.jar` 放入实际游戏实例的 `mods` 文件夹，移出旧版桥接 JAR。Fabric 同时安装对应 Fabric API，NeoForge 无需 Fabric API。模组需要 Python 3.10+ 并包含 pip。启动后先检测 Python；如果缺少，则等玩家进入单人世界时显示安装页面并暂停该世界，可用关闭按钮或 Esc 暂时关闭。检测到 Python 后会提示 MCDR 自动安装状态，并准备 MCDR 2.16.0、桥接插件与运行依赖。Windows x64 页面提供 Python 3.14.8 当前稳定版的官方下载直链和阿里云镜像，其他系统跳转 Python 下载页。PB / CB 在首次进入世界后点击聊天中的安装按钮安装；已有兼容版本保留并更新对应单人适配器。不需要开放局域网。

首次下载耗时取决于网络。进度在 `mcdr-singleplayer/log/bootstrap.log`，错误与镜像切换记录在 `mcdr-singleplayer/log/install.log`。安装失败保留日志，下次启动重试；游戏本身仍可使用。

模组设置文件 `mcdr-singleplayer-config.yml`、MCDR 的 `config.yml`、`permission.yml` 和 `plugins/` 直接位于 `mcdr-singleplayer/` 根目录。`date/` 中每个子文件夹是对应存档的 MCDR 工作目录，插件配置和数据保留原有相对路径。运行环境归入 `runtime/`，日志归入 `log/`：

```yaml
# 本机回环连接端口；发生冲突时可修改
port: 25585
# 随机身份验证令牌，请勿分享或公开
token: "保留首次生成的随机令牌"
# 进入单人存档时自动启动 MCDR
autoStartMcdr: true
# 自动准备 MCDR、桥接插件及运行依赖
autoInstall: true
# 可选的 Python 可执行文件路径；留空时自动检测
pythonExecutable: ""
```

不要照抄示例 token。生成的配置文件会为每项设置添加中文备注。`pythonExecutable` 为空时寻找已安装的 Python 3.10+ 和 pip，也会检查 Windows 常见安装目录；找不到时不会自动下载或安装 Python。进入单人世界后会提示安装，Windows x64 可选择 Python 3.14.8 官方直链或阿里云镜像，其他系统需自行选择对应安装包。安装器的 `Optional Features` 页面务必勾选 `pip`，首页建议勾选 `Add python.exe to PATH`。检测到安装后模组会自动继续启动；不会修改全局 Python 软件包。

这份设置保存在 `mcdr-singleplayer/mcdr-singleplayer-config.yml`。首次升级时会自动迁移旧版 `config.json`，并将原文件保存在 `runtime/migration-history/`。

游戏启动时启动常驻控制器。在主菜单等待，进入单人存档后才创建该存档的 MCDR 进程并加载插件。保存退出后等待插件任务结束，退出该进程，控制器继续等待。重新进入或切换存档会自动启动对应环境。退出客户端后控制器等待未完成的备份/回档任务结束再退出。

## 文件布局

```text
游戏实例/mcdr-singleplayer/
  mcdr-singleplayer-config.yml  # 本模组设置及字段备注
  config.yml                    # 共用 MCDR 设置
  permission.yml                # 共用玩家权限
  download-sources.json         # 可选下载镜像配置
  plugins/                      # 共用插件文件
  date/
    存档文件夹名称/
      profile.json              # 实际存档绑定
      config/<插件 ID>/         # 原生插件配置/API 数据
      pb_files/                 # PB 原生数据库与备份文件池
      cb_files/                 # CB 原生备份槽位（安装 CB 后创建）
      其他插件原生相对路径/      # 沿用各插件自己的目录名称
  log/
    bootstrap.log
    install.log
    controller.log
    存档文件夹名称/
      controller-child.log
      MCDR.log
  runtime/
    .bridge-venv/               # 独立 Python 和依赖
    bridge-runtime/             # 控制器、代理和辅助程序
    bootstrap-resources-0.3.9/  # 安装和更新材料
    runtime-install.json
    .mcdr_restore_progress.json
    .mcdr_restore_locks.json
    .mcdr_bridge_session.json
    .controller.lock
    .installation.lock
```

`runtime/bootstrap-resources-0.3.9/` 是模组首次启动时解出的安装材料，包含 MCDR 插件、备份适配器、Python 启动脚本和依赖清单。MCDR 环境随后安装到 `runtime/bridge-runtime/`，Python 及其依赖装在 `runtime/.bridge-venv/`。`mcdr-singleplayer/` 根目录中存放本模组、MCDR 的共用设置、权限和插件；它们仍都位于 `mcdr-singleplayer/` 内。

存档按游戏 `saves/` 的文件夹名分类，而不是按世界显示名称。每个存档的插件设置和备份都放在 `date/<存档文件夹名>/`。MCDR 插件 API 会将自身设置及部分数据放入 `config/<插件 ID>/`，因此该目录可能同时含有这两类文件。

MCDR 的控制台和核心日志统一写到 `log/<存档文件夹名>/`。插件自己指定了其他日志或数据绝对路径时，需要在该插件的设置中改用相对路径或存档目录。

## 从旧版升级

0.3.7 起将 `runtime/config/` 内的共用设置与插件迁移到根目录，保留令牌、权限和用户设置；将桥接曾引入的 `date/<存档名>/data/prime_backup/` 移到 `pb_files/`，`data/chunk_backup/` 移到 `cb_files/`，同步对应插件的 `storage_root`。其他插件的原生路径与用户自定义存储位置保留。原生和旧备份目录同时非空时停止迁移，不合并数据库或覆盖备份；关闭客户端并结束 MCDR 后再处理冲突。

关闭客户端并等待备份、回档结束，再替换 JAR；新旧 JAR 不可同时安装。首次启动将旧 `config/mcdr_singleplayer_bridge.json` 和同目录的桥接状态、回档锁转移到 `mcdr-singleplayer/`。新配置已存在时保留新配置，旧配置归档在 `mcdr-singleplayer/runtime/migration-history/`，回档锁合并。

从旧配置指向的 MCDR 目录导入共用插件、MCDR 设置、权限，以及 `worlds/<存档文件夹名>/` 中已有的配置、插件数据、备份数据库和文件池。导入后 PB 的备份存储位置改为新分类目录中的对应位置，自定义备份策略与开启/关闭选择保留。目标分类目录已存在且不是本次导入生成时停止迁移，不覆盖数据。

旧 MCDR 目录仅作为迁移来源保留，可能还供专用服务器使用；本模组此后的运行和配置修改只使用游戏中的新目录。模组不会删除原专用服务器文件。旧版游戏 `config/` 中的模组设置与状态文件会移走，不留下第二份活动配置。迁移日志见 `mcdr-singleplayer/log/install.log`，完成记录为 `mcdr-singleplayer/runtime/.legacy-layout.json`。若旧回档仍在运行，模组暂缓移动配置，继续读取旧回档进度并阻止打开目标存档；锁的新增状态只写入新目录，回档结束后重启客户端继续迁移。

分类使用存档文件夹名，不使用 `level.dat` 中的显示名称。若不同实例存在同名且实际路径不同的存档，控制器报错，避免共用数据；需要修改其中一个存档文件夹名。

MCDR 的插件 API 本身把部分数据写在 `config/<插件 ID>` 下，因此该文件夹可能同时包含配置和数据。每个存档使用不同的进程工作目录，相对路径均隔离。其他插件自行指定的绝对目录需要改成相对路径或该存档的目录；程序不能通用地重写任意插件的自定义路径。

首次安装会修改 `config.yml` 中启动桥接所需的项目；不再生成 MCDR 默认配置的 `config.yml.before-*` 副本，也会清理旧版已生成的这类副本。进入世界时语言跟随客户端，单人主玩家加入同一个共用 `permission.yml` 的 `owner` 列表。已有 owner 保留；局域网其他玩家沿用原有权限。权限更改记录保存在 `runtime/history/`。

## 推荐配置与手动配置

点击安装 Prime Backup 后，新存档默认 `enabled: true`，存档位置与独立备份目录自动绑定，使用 `save-off / save-all flush / save-on` 完成保存与备份。0.3.2 首次接管旧版存档分类时也应用推荐配置并备份原配置，此后重新进入不会重置选择。

语言使用单人玩家的客户端语言代码，MCDR 与 PB 的玩家消息跟随该语言；没有对应译文时使用它们自身的回退译文。单人主玩家默认最高 MCDR 权限 `owner`（4）。

首次进入世界后，左下角聊天说明数据位置、主玩家四级权限、按存档隔离的配置与数据、彻底删除存档后需手动清理 `mcdr-singleplayer/date/<存档名>/`。测试阶段必须保留其他完整备份的警告显示三次。

缺少的插件显示官方主页链接和 `[安装]`：PB 安装官方 1.13.1 与单人适配器；CB 安装官方 2.0.3、candy_tools 1.0.2 与单人适配器。安装在 Python 后台线程执行，固定下载哈希校验，失败可重试，保存现有不同版本的插件。

PB 已安装并加载时，在上述提示之后显示配置按钮；新安装 PB 后也立即显示：

- `[开启Prime Backup]`：启用当前存档 PB。
- `[启用4小时定时备份]`：每 4 小时备份一次。
- `[启用推荐的自动删除]`：保留最近 40 份、每日 1 份保留 30 天、每周 1 份保留 30 周；清理间隔 6 小时。
- `[点击查看Prime Backup官方文档]`：打开官方插件页面。

自动备份、自动删除默认关闭，选择按存档保存。`[忽略且不再主动提示]` 在根目录 `mcdr-singleplayer-config.yml` 保存 `onboardingDismissed`，对同一游戏实例的全部存档生效；未忽略时说明每次客户端启动后显示一次，PB 配置选项按存档会话显示。可随时使用 `/!!spbridge onboarding show` 主动查看，或 `/!!spbridge install prime_backup`、`/!!spbridge install chunk_backup` 安装。安装要求 MCDR 最高权限（4）。

清理使用 PB 原生 `last: 40 / day: 30 / week: 30`，三种保留规则合并，`40` 并非总备份数量上限。手动和定时产生的普通备份共用这一保留池，不另设第二套定时备份清理规则。PB 标为保护的备份和回档前的临时安全备份保留。

进入世界执行：

```text
/mcdr_setup recommend
```

此命令再次应用推荐配置并显示配置选项与官方文档按钮，保留之前的开启/关闭选择。已有 PB 配置先备份，再重载 PB 与适配插件。也可通过指令切换：

```text
/!!spbridge config backup on
/!!spbridge config backup off
/!!spbridge config auto_backup on
/!!spbridge config auto_backup off
/!!spbridge config auto_delete on
/!!spbridge config auto_delete off
```

也可以直接编辑 `mcdr-singleplayer/date/<存档文件夹名>/config/prime_backup/config.json`，重新进入存档生效。`backup.source_root` 应为存档的父目录，`targets` 只填写当前存档文件夹名，`source_root_use_mcdr_working_directory` 必须为 false，`storage_root` 必须在当前配置分类目录内。无效绑定会阻止该存档的 MCDR 启动。

主玩家不必执行授权指令。`/mcdr_setup owner` 保留为手动重新授权入口；自动识别基于本地客户端账号，不按玩家加入顺序选人。

## 斜杠命令与补全

读取当前 MCDR 注册的完整命令图：所有插件根命令、别名、字面量子指令、参数节点及重定向均注册到客户端。输入 `/!!` 并按 Tab，可补全 MCDR、PB 和其他插件的指令；例如新插件注册 `!!example nested leaf` 后可直接使用 `/!!example nested leaf`，无需修改本模组。

加载、卸载、重载插件后通常半秒内同步，卸载的命令从客户端注册表移除。参数建议由 MCDR 的实际建议接口返回，包括插件 ID、玩家名与插件自定义建议。执行仍交给 MCDR 检查共用 `permission.yml` 和插件自身要求；聊天形式的 `!!MCDR`、`!!pb` 也继续可用。与其他客户端模组根命令重名时保留先注册的客户端命令，该 MCDR 根命令可继续用聊天形式执行。

```text
/!!MCDR plugin list
/!!MCDR plugin reload prime_backup
/!!pb make 手动备份
/!!spbridge status
```

只在当前单人世界桥接连接后可执行。补全请求最多等待两秒；模组不会缓存其他世界的建议。原生回档流程仍有确认、保存、退出和完整性验证；回档完成后手动进入原世界，MCDR 自动连接。

## 主菜单回档提示与存档入口锁

0.3.9 的可选 Chunk Backup 2.0.3 适配器也使用此界面与入口锁，覆盖 `!!cb back` 和 `!!cb restore`；安装与绑定见 [Chunk Backup 适配](ChunkBackup适配.md)。控制器同时等待 PB / CB 任务完成，两个插件的备份和回档互斥。

执行 `/!!pb back <备份 ID>` 并确认后，先保存退出世界，再创建回档前安全备份，最后恢复并校验文件。世界退出后，使用原版菜单背景、灰白文字和按钮，在主菜单中央显示目标存档、备份 ID 和实际阶段；原版点状等待动画表示仍在处理，不显示估算百分比。回档中主菜单按钮暂时停用，同时存档打开入口也会拦截目标存档，避免快捷入口提前加载文件。

成功时显示“回档完成，可以重新进入存档”。点击“返回主菜单”，再手动进入原存档；MCDR 自动启动。取消或未确认不会显示成功。失败时显示错误原因；若文件恢复已开始，目标存档保持锁定，需要通过原 MCDR 环境成功离线重新回档后才能进入。只有检查失败、尚未修改文件的情况可以直接返回。

状态保存在游戏 `mcdr-singleplayer/runtime/.mcdr_restore_progress.json`，文件恢复后产生的入口锁保存在 `mcdr-singleplayer/runtime/.mcdr_restore_locks.json`。退出世界、MCDR 断开或客户端重启不会把失败当成完成。不要在未修复存档时手动删除锁文件。

自动模式下的失败重试：先保持游戏在主菜单，等待该存档 `controller-child.log` 中出现 `bye`。用实际路径替换下面的游戏配置和存档文件夹名，在 PowerShell 中启动原存档的 MCDR 环境：

```powershell
$bridgeCommon = 'D:/你的游戏实例/mcdr-singleplayer'
$env:MCDR_BRIDGE_CONFIG = 'D:/你的游戏实例/mcdr-singleplayer/mcdr-singleplayer-config.yml'
$env:MCDR_BRIDGE_RUNTIME = Join-Path $bridgeCommon 'runtime'
$env:MCDR_BRIDGE_LOG_DIR = Join-Path $bridgeCommon 'log/你的存档文件夹名'
New-Item -ItemType Directory -Force -Path $env:MCDR_BRIDGE_LOG_DIR | Out-Null
Push-Location (Join-Path $bridgeCommon 'date/你的存档文件夹名')
try {
  & (Join-Path $bridgeCommon 'runtime/.bridge-venv/Scripts/python.exe') -c 'import os; from mcdreforged.constants import core_constant; core_constant.LOGGING_FILE=os.path.join(os.environ["MCDR_BRIDGE_LOG_DIR"], "MCDR.log"); from mcdreforged import mcdr_entrypoint; mcdr_entrypoint.entrypoint()' start --config (Join-Path $bridgeCommon 'config.yml') --permission (Join-Path $bridgeCommon 'permission.yml')
} finally {
  Pop-Location
  Remove-Item Env:MCDR_BRIDGE_CONFIG
}
```

在这个 MCDR 控制台用 `!!pb list` 选择完整备份，再输入 `!!pb back <ID> --confirm`。成功后主菜单提示完成并解除该存档入口锁；输入 `!!MCDR server stop_exit` 退出手动重试环境，再进入存档。原存档绑定、文件校验与 `session.lock` 检查仍生效。

## 导入另一个存档的配置

需要 MCDR admin 或 owner：

```text
/!!spbridge profile list
/!!spbridge profile import "另一个存档文件夹名"
/!!spbridge profile import "另一个存档文件夹名" --replace
```

默认只导入当前存档缺少的文件。`--replace` 会先备份当前文件再替换。导入后下次进入存档生效。不会修改共用插件、MCDR 设置或权限。

默认识别文件主名为 `config`、`settings`、`options` 或以 `.config`、`.settings` 结尾，扩展名为 JSON/YAML/TOML/INI/CFG/CONF/properties 的配置文件。跳过数据库、备份文件池、数据/cache/backups/database 目录、其他命名的状态文件与桥接自身绑定。插件自定义命名的配置可自行复制；无法可靠识别的文件不自动导入。拒绝符号链接和 Windows 目录联接。

导入 Prime Backup 配置时会重新绑定当前存档与独立备份目录，保留源配置的策略，不导入它的备份数据库。备份任务执行期间拒绝配置导入与推荐配置。

## 下载与更新

依赖安装依次使用 PyPI、清华、阿里索引；下载失败或安装超时自动换下一个。Prime Backup 先使用 GitHub 官方发行文件，再尝试 GitHub 代理镜像，所有下载必须匹配已验证发行版的 SHA-256。可在共用目录的 `download-sources.json` 自定义镜像前缀，例如：

```json
{"github_mirrors": ["https://gh-proxy.com/"]}
```

缺少 Python 时不会由模组下载或静默安装解释器，需通过游戏中的安装页选择 Python 官方链接或镜像。

首次启动、依赖清单改变或距上次检查超过一天时，更新到本模组声明的兼容版本及其依赖。目前兼容通道固定 MCDR 2.16.0 / Prime Backup 1.13.1；不自动升级到未经适配的 Prime Backup 1.14。发现共用目录已有其他 Prime Backup 版本时保留文件，点击安装会提示兼容性问题，避免重复插件 ID 和不兼容回档。

## 手动模式

将 `autoStartMcdr` 改为 false，可继续使用之前的手动 MCDR 安装流程。`setup_mcdr.py` 明确选择手动模式，并在游戏配置中关闭自动启动。不要同时启动两个控制器管理同一个共用目录。

## 0.3.9 语言资源

首次说明、配置按钮、命令反馈、模组自身的校验错误和回档界面支持 `zh_cn`、`zh_tw`、`en_us`，跟随进入存档时的客户端语言；缺少译文时使用英文。提示文本去除句号，以分行或逗号分隔，路径与版本号中的点保留。语言文件由 JAR 和 Python 插件携带，配置仍只在 `mcdr-singleplayer/` 内。
