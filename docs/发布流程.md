# 自动发布

发布流程参考 [RankBoard](https://github.com/halfkite/rankboard) 的独立 Fabric / NeoForge 工作流，发布目标是本项目的 GitHub Release 与 CurseForge 项目 **1723660**

## 四个分发文件

| 加载器 | 游戏版本系列 | 文件名 |
| --- | --- | --- |
| Fabric | 1.21–1.21.11 | `mcdr-singleplayer-<版本>+fabric+mc1.21.x.jar` |
| NeoForge | 1.21–1.21.11 | `mcdr-singleplayer-<版本>+neoforge+mc1.21.x.jar` |
| Fabric | 26.1、26.1.1、26.1.2、26.2、26.3 | `mcdr-singleplayer-<版本>+fabric+mc26.x.jar` |
| NeoForge | 26.1、26.1.1、26.1.2、26.2、26.3 | `mcdr-singleplayer-<版本>+neoforge+mc26.x.jar` |

同系列所有受支持版本共用一个 JAR，文件内部包含独立编译的版本实现，只加载当前游戏对应的实现与 Mixin

支持的是 `compat/versions.json` 明确列出的稳定版本，不自动宣称支持之后发布的新版本、快照或预发布版

## 发布步骤

1. 同步 `compat/versions.json` 的 `modVersion`、`fabric-bridge/gradle.properties`、Python 与两个适配插件的版本号，更新三语言 README 和测试记录
2. 运行 Python 测试、Java 测试、四组系列构建、`python scripts/verify_artifacts.py` 与指定版本客户端测试
3. 将通过验证的源码提交到 GitHub，为该提交创建版本 tag，如 `v0.3.10`
4. 在 GitHub 发布同 tag 的 Release，填写更新说明；初步测试版本建议勾选 Pre-release
5. `release.yml` 和 `release-neoforge.yml` 自动运行，各自构建两个系列并附加 JAR 和 SHA-256 校验文件到该 Release，再上传到 CurseForge

工作流只接受已经发布的 Release，tag 去除 `v` 后必须与该 tag 中 `compat/versions.json` 的版本完全一致

Pre-release 对应 CurseForge `beta`，普通 Release 对应 `release`，更新说明使用 GitHub Release 的正文

CurseForge 文件关联该系列全部明确游戏版本、对应加载器和 `Client` 标签，项目 ID 由版本清单读取

## 密钥

仓库 Actions Secret 名为 `CURSEFORGE_TOKEN`，值为 CurseForge 官方上传 API key

只从 Actions Secret 读取，不写入仓库、配置文件、JAR 或日志，也不放入工作流输入参数

缺少 Secret 时，GitHub 附件仍可上传，CurseForge 步骤会明确失败，不伪装成发布成功

本项目尚未提供 Modrinth 项目 ID，因此未配置 Modrinth 自动上传

## 补发

在 Actions 中手动运行 `Publish mcdr-singleplayer Fabric` 或 `Publish mcdr-singleplayer NeoForge`，填写已经发布的 Release tag

取消 `curseforge` 选项时只更新 GitHub 附件；开启时也会上传 CurseForge，新上传可能生成新文件记录，避免无必要重复执行

GitHub 附件允许覆盖同名构建；不同系列、加载器的文件名彼此独立

## 构建环境

工作流使用 Java 25 运行 Gradle，另安装 Java 21 用于 1.21.x 的 NeoForge 工具链；1.21.x 字节码目标为 Java 21，26.x 为 Java 25

构建源按版本生成到 `build/matrix/`，最终系列包输出到 `dist/`，每次成功构建另归档到 `mod-builds/<时间戳>/` 并记录哈希

本地使用 Codex 的 build-game-mods 归档器；CI 无该技能时使用仓库内的 `scripts/archive_build.py`

Python 依赖只用于构建测试，安装器中的运行环境仍按已固定依赖和下载校验策略准备

官方接口参考：[CurseForge Upload API](https://support.curseforge.com/support/solutions/articles/9000197321-curseforge-upload-api)
